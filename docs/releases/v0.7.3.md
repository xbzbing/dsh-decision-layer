## 主要变更

- **决策日志的「场景」改为本回合的真实请求**：长会话里不再回落到会话第一条消息——只有 `source.kind=user` 的真实输入算任务，时间 / 运行环境 / 记忆 / 后台通知 / 插件 steer 都不计入；同一个回合内出现新请求时收窄会以新请求重判。收窄行带步号，面板显示「回合 N · 第 N 步」。
- **完成核对只看本轮**：交付条件逐条取自最近一次用户请求，工具证据只取回合边界之后、以调用 ID 关联到工具名，并带上 command / path 与 shell 结果节选；历史被 rewind 或压缩替换后证据保守清空，不再用上一个任务的成功为新任务背书。
- **工具限制在回合结束释放**：被中止或失败的回合也会在 `turn/end` 释放收窄限制；同一回合出现新请求时先释放旧限制再重判（新判定从下一步生效——宿主在本步 `pre-step` 之前已解析工具集），避免旧 allow-list 把工具永久锁死。
- **内部**：新增 ADR-0016 记录来源判定、回合边界、证据窗口与日志字段；自检与完成核对的外发请求新增本轮请求 / 背景与 shell 结果节选（均截断并掩码）；修复带引号的 JSON / `.env` 写法（`{"DB_PASSWORD":"…"}`、`DB_PASSWORD="…"`）里的凭据遮蔽；日志行新增 `step` 字段。

## English

- **Decision logs now show the turn's real request**: in a long session the task no longer falls back to the first message — only input with `source.kind=user` counts as a task, so time / runtime / memory / background notices and plugin steers are ignored; when a new request arrives mid-turn, narrowing re-judges against it. Narrowing rows carry a step number and the panel shows "Turn N · step N".
- **Completion only looks at the current turn**: delivery conditions come from the latest user request, tool evidence only from after the turn boundary, tied to tool names via call IDs and carrying command / path plus shell result excerpts; after a rewind or compaction the evidence is conservatively cleared, so an earlier task's success can no longer vouch for a new one.
- **Tool restrictions are released at turn end**: an aborted or failed turn now releases the narrowing restriction on `turn/end`; a mid-turn new request releases the old restriction before re-judging (the new verdict takes effect from the next step, since the host resolves this step's tool set before `pre-step`), so a stale allow-list can never lock tools out permanently.
- **Internal**: ADR-0016 records the provenance rule, turn boundary, evidence window and log fields; self-check and completion requests now include the turn's request / background and shell result excerpts (truncated and masked); quoted JSON / `.env` credential forms (`{"DB_PASSWORD":"…"}`, `DB_PASSWORD="…"`) are masked; log rows gain a `step` field.
