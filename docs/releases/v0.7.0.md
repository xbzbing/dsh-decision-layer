## 主要变更

- **各决策点的介入阈值全部可配置**：新增 `gateSettings.minConfidence`（门控拦截置信度，默认 0.6，原为硬编码常量）、`checkSettings.minConfidence`、`completeSettings.minConfidence`（默认 0.4）；配置页补上原先只能手改 `config.json` 的 `rubric`、`lowScoreThreshold`、`trendMinConfidence` / `trendRun` / `trendSevereRun`、`minConditions`、`batchMode`。门控阈值改为按次解析，改配置即生效、无需重启。
- **配置写坏不再让每个工具调用失败**：`featureOn` 位于宿主 `tools/pre-execute` 瀑布内，抛错会被转成 `toolErrorResult` 且工具不派发——写错一个配置值就会失去全部工具（含 `read` / `edit`，连修配置都做不到）。现在配置读取失败退化为「全部功能开启 + 各决策点自己的安全默认」，安全网保持有效，同时不拖垮 agent。
- **产物移出仓库，发布交给 GitHub Actions**：`lib/` 不再提交，`npm pack` 前由 CI 构建，`scripts/assert-pack.mjs` 断言产物含 `lib/client.js` 且无源码泄漏。新增 CI（Node 22/24）与 `release.yml`（仅手动触发、默认 `dry_run=true`）。**破坏性**：不带 ref 的 `github:xbzbing/dsh-decision-layer` 安装不再可用，GitHub 侧请用 Release 附件 tgz。
- **dock 触发器与官方上下文用量指示同时出现**：会话还没有上下文读数时这一行是空的，不再单独露出「决策」按钮。
- **配置项校验更明确**：`rubric` 不足 2 档 / 超 10 档 / 单档超 256 字时给出具体提示并阻止保存，不再静默替换或截断；保存失败会带上服务端原因。
- **新增架构决策记录**：`docs/adr/` 收录 13 份 ADR（门控两档模型、失败即放行与爆炸半径、配置整段替换、收窄三重保护、分发渠道等），说明每条规则为什么存在、放弃了哪些备选。

## English

- **Every intervention threshold is now configurable**: new `gateSettings.minConfidence` (danger-gate block confidence, default 0.6, previously a hardcoded constant), `checkSettings.minConfidence` and `completeSettings.minConfidence` (default 0.4); the config page now exposes what previously required hand-editing `config.json` — `rubric`, `lowScoreThreshold`, `trendMinConfidence` / `trendRun` / `trendSevereRun`, `minConditions`, `batchMode`. The gate floor is resolved per call, so a config edit takes effect without a restart.
- **A broken config no longer fails every tool call**: `featureOn` runs inside the host's `tools/pre-execute` waterfall, where a throw becomes a failed call with the tool never dispatching — one bad value used to cost every tool, including `read` / `edit`, so the file could not even be repaired. An unreadable config now degrades to "all features on plus each decision point's own safe default", keeping the safety net armed without taking the agent's tools away.
- **Build output moved out of the repository; releases run in GitHub Actions**: `lib/` is no longer committed, CI builds it before `npm pack`, and `scripts/assert-pack.mjs` asserts the tarball carries `lib/client.js` and leaks no sources. Adds CI (Node 22/24) and a manual-only `release.yml` that defaults to `dry_run=true`. **Breaking**: installing `github:xbzbing/dsh-decision-layer` without a ref no longer works; use the Release tarball instead.
- **The dock trigger appears together with the official context meter**: while a session has no context reading yet, the row stays empty instead of showing a lone "decisions" button.
- **Clearer config validation**: `rubric` with fewer than 2 levels, more than 10, or a level over 256 characters now blocks the save with a specific message instead of being silently rewritten or truncated; a failed save also surfaces the server's reason.
- **Architecture decision records added**: `docs/adr/` holds 13 ADRs (two-tier gate, fail-open with a bounded blast radius, wholesale config replacement, narrowing safeguards, distribution channels), recording why each rule exists and what was rejected.
