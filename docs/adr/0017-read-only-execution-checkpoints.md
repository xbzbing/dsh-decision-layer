# ADR-0017：以有界只读检查点评估同回合执行过程

- 状态：Accepted（2026-11-06）
- 相关：ADR-0002、ADR-0004、ADR-0008、ADR-0009、ADR-0011、ADR-0016
- 代码：`src/host/execution-observer.ts`、`src/host/checkpoint-review.ts`、`src/host/log-row.ts`、`src/host/evaluation-trace.ts`、`src/host/index.ts`、`src/client/{config-form,decision-log,analysis-view}.tsx`
- 范围：M0 + M2-lite。跨回合任务账本、统一干预仲裁、阶段化收窄不在本次实施范围。

## Context

回合末自检收到请求、前文和最终回复，不包含工具进展。长回合持续执行工具期间没有中途检查；工具收窄仅在首步或新真实用户要求时重判。现有日志缺少请求耗时、usage 和可核对的动作关联，不能用调用量证明执行收益。

可选方案是每步调用模型、把完整历史交给评分器、另起规划 Agent，或只观察少量关键检查点。前三者分别增加重复调用、扩大数据范围、超出结构化裁决定位。本次选择最后一种，先验证对持续失败和验证失效的检出能力。

DSH 当前安装版的 session/event 是提交后同步通知，返回 Promise 不会阻塞 loop，事件发布内重入 append 会失败。step/end 在 finally 中产生，不表示步骤成功；tool/result 没有工具名，需按 callId 关联。工具已在 pre-step 之前解析，本提案不修改工具集合或模型消息。

## Decision

1. 新增独立 `checkpointSettings`，默认关闭。用户显式开启后只读观察当前回合，仍受会话总开关控制；坏配置关闭新增能力。参数为 heartbeatSteps（默认 6，2–100）、failureThreshold（默认 3，2–10）、timeoutMs（默认 1500，100–10000）。固定滚动 24 步最多 4 次检查，全局最多 4 个在途检查；这些值是实验起点，不是验证过的最优值。
2. pre-step 使用 ADR-0016 的有效请求来源绑定当前 agent/session/turn；没有本轮真实要求不创建任务。事件观察按 session 对象与 seq 隔离，工具调用与结果有界关联。只从已提交工具结果生成进展，不把通知、空步骤、assistant 自述或恢复合成错误当成功证据。
3. 在 step/end 聚合，合并心跳、持续未解决失败、验证后又修改产物三类候选。单次失败可属于正常探索；修改后待验证只是观察信号。成功重跑解除相同策略失败，旧验证不能证明修改后产物仍正确。纯分析任务不据无工具进展推断卡住。
4. 事件回调只更新内存、安排微任务。每会话最多一个在途检查和一个最新候选，后台评估共享短截止时间。失败即跳过，不 steer/inject/append/restrict，不修改原有门控、收窄、自检或完成核对行为。新要求、压缩/rewind/表面替换、turn/end、会话关闭、session dispose 和插件卸载取消工作；晚到/过期结果不更新活动判断、不唤醒 agent。
5. 继续使用 backend.evaluate 的唯一 wire 校验和 choice 题型，固定题目和候选枚举，不期待后端返回自然语言诊断或证据 id。有效 concern 仍需置信度；低置信结果显示 uncertain。跳过不计裁决尝试，也不进入最终回复质量趋势；取消/过期结果归入跳过并带独立原因，不冒充后端失败。
6. 外发请求仅含有界脱敏的当前要求与当前窗口执行摘要：工具名、成败、有限命令/路径、shell 摘录。不发文件读取/搜索/网页结果原文、reasoning、system/developer/记忆或 PTC 脚本。按字段与总量限制请求，省略明确标记；小模型超限保持失败放行。现有门控外发范围不扩大。
7. 为自动裁决记录 requestId、model、请求字节、总耗时、实际后端请求次数和可用 usage；失败也保留已知测量。字段缺失保持 unknown，不补造零；`confidence` 表示该 verdict 的模型置信度，不再只用于低置信行。shell 成功不附带退出码标记，无标记即宿主约定的干净退出 0；只有简单单命令且确知退出 0 才算验证事实。记录成功 steer/工具 callId 等动作关联，表明宿主接纳，不宣称修复成功。过程检查独立日志 kind=checkpoint，沿用 JSONL/快照/人工标注，浏览器只接收白名单标量与既有任务节选，原始过程证据不持久化或回传。
8. 所有新增状态和队列有界，配置每次现读，恢复只恢复日志计数，不恢复在途检查。无受支持事件的旧宿主保持原有决策点，不臆造事件或调用。

## Consequences

长回合可在没有新用户输入时产生中途评估，且每次结果可追溯触发点和执行窗口。代价是启用后增加有限外发和裁决成本，需要中英文隐私说明、配置开关和独立只读标识。

此切片只能验证判断是否发现了值得关注的问题，不能证明纠偏收益。后续需外部验收条件、人工标注及受控任务对照；若没有稳定增量，不开放自动干预。跨回合账本和统一仲裁须另写 ADR，不提前改变现有每回合各一次补完合同。

验收包含：默认关闭零请求、同轮中途检查、来源隔离、工具配对、非零退出与未知结果、重试恢复、修改后旧验证失效、去重/合并/预算/超时、开关/取消/过期抑制、清理与兼容、脱敏与请求预算、旧日志恢复、前后端白名单和只读标注；完成 npm run check 与隔离宿主验证。
