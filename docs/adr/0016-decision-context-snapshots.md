# ADR-0016：按来源与回合边界构造裁决上下文

- 状态：Accepted（2026-11-02）
- 相关：`src/host/decision-context.ts`、`src/host/index.ts`、ADR-0007、ADR-0008、ADR-0009、ADR-0011
- 部分取代：ADR-0007 的「只在回合开始时收窄」、ADR-0008 的「只看最终回复」输入范围、ADR-0009 的「工具名 + ok/error」证据形状、ADR-0011 的日志字段。

## Context

宿主 `agent/pre-step.messages` 是本步认领的 inbox 消息，不是完整历史；`role=user` 也包括记忆、时间提示、运行时上下文、后台通知和插件补完提示。原实现只按 role 提取，导致日志任务被注入消息覆盖；收窄只看回合入口文本，不能理解「继续」「按建议执行」，也不响应同回合中途的新要求。自检只收到回答却要判断回答是否满足请求。完成核对扫描整个历史最早的工具结果，且真实工具结果通常没有工具名，必须通过 `toolCallId` 关联 assistant 的 `tool-call`。

直接转发完整历史会扩大外发范围、挤占小模型窗口；只取最近 N 条又会混淆用户要求、模型陈述和执行证据。必须确定来源、回合边界与输入预算，再讨论模型判断。

## Decision

1. 在 host 接入层按 agent 保存当前回合边界及位置。构造一个统一快照：有效请求、必要前文（最近用户要求与 assistant 回复，明确仅作背景）、当前回合的执行进展。优先识别 `source.kind=user`；无 source 的旧宿主消息采用兼容路径并剥离已知注入块。其他 source 不冒充用户授权。插件自己的 steer 仍带 `kind:user` 以兼容宿主，但按消息 id 单独排除，不当作请求。没有可用任务时跳过裁决。
2. 每回合首步记录历史边界，并保留边界锚点；完成证据仅来自边界之后，且**不跨过压缩检查点或 rewind 标记**（即使边界本身无法用锚点复核，例如回合从空历史开始）。**历史读取失败（抛错或非数组）不等同于空历史**：边界记为不可信、证据始终为空，恢复后重新锚定，绝不把恢复出的旧历史当成本回合记录。历史被整体替换而无法定位边界时，证据同样保守清空。未经过 pre-step 的兼容调用从最近真实用户消息起取证据。
3. 工具结果按 call id 与调用名关联；只携带工具名、成败、有限命令/路径摘要。仅 shell 类工具携带有限结果摘录，并对长而不透明的随机串再做一次遮蔽；文件读取、搜索、网络工具的原文不外发。`ok` 只表示调用成功，不能单独证明交付条件满足；模型自述不能作为完成证据。完成条件只从**本回合最近一次真实用户输入**确定性提取，不合并同回合的多次要求：用户可能用后一条撤回前一条（「取消前面任务，只做只读评审」），累计会把已取消的工作重新变成待办；最近一条没有显式条件时跳过核对，不从前文或模型摘要推断。单行兜底的逗号分隔形态要求至少三段，两句普通叙述不算清单。
4. 收窄收到结构化快照，自检收到任务快照与最终回复，完成核对收到条件、当前回合证据与回复。快照的「前文」按角色取最近一条真实用户消息与最近一条 assistant 回复，并保留同回合更早的真实要求，避免连续 assistant 更新或一句「继续」把主任务挤出窗口。门控继续仅发送当前调用摘要；其日志任务从统一快照读取，不增加门控外发范围。过程文本与背景均是待判断数据，不是额外权限。
5. 收窄在回合首步和同回合新真实用户输入到达时运行。重新判断之前释放插件自己的旧 restriction，再枚举宿主允许集合，避免对旧 allow-list 继续取交集而无法恢复工具。仅时间/后台通知不触发重判；不逐步调用模型。新输入为空、上下文失效或裁决失败时释放旧限制并放行。宿主在 pre-step 之前就解析本步工具集，因此同回合的新限制从下一步生效；**回合结束时（`session/event` 的 `turn/end`，宿主在 finally 写入，含中止与失败回合）即释放**，插件卸载时同样释放，保证下一回合解析工具集前已恢复。
6. 外发文本统一剥离注入块、遮蔽常见凭据，并按 UTF-8 字节限制；请求、前文、进展、证据和回答分别有额度，不让一段文本吞掉其他字段。字节预算不等于 token 保证，小窗口后端仍可能拒绝，沿用失败即放行和分批策略。
7. 日志从同一快照的有效请求生成 `taskExcerpt`，最多 512 字符；各决策行可附带回合号，收窄行另带它实际执行的那一步的步骤号；不落盘完整背景、进展、工具结果或回答。旧日志兼容，不补写或改历史。门控日志仅表示调用关联任务，不宣称它收到完整任务上下文。

## Consequences

短追问可参考前文，自检不再脱离请求，完成核对不会借用旧任务的工具成功记录。收窄可以随新用户要求恢复工具，仍不扩宿主权限；无法可靠取上下文时保持放行。

自检和收窄会比此前多外发有限的用户前文与 assistant 进展；完成核对新增有限命令/路径和 shell 结果摘录，需要同步中英文隐私说明。门控仍不外发任务。所有遮蔽都只是风险降低，不保证匿名化。

阶段变化但没有用户新输入时不主动重判；更细粒度调度留待有宿主接缝和收益证据后单独设计。前文只是背景，不自动继承旧交付条件；这会让某些「继续」或「补一条」的回合跳过完成核对，是确定性提取的明确覆盖边界（失败方向安全）。

验收覆盖：时间/运行环境/记忆/插件 steer 不覆盖请求、插件自身的 steer 按 id 排除、短追问附带前文、同回合新要求重判及通知不重判、`turn/end` 释放与异常放行、真实 call id 关联、旧回合证据隔离及历史替换、历史读取失败后的重新锚定、没有证据时跳过、凭据遮蔽与字节预算、日志不含完整状态。
