# ADR-0008：自检用概率加权分，低置信低分视为噪声

- 状态：Accepted（2026-10-26）
- 相关：`service/self-check.mjs`、`service/quality-trend.mjs`、`service/steer-once.mjs`、ADR-0002、ADR-0006

## Context

回合结束后给「这次回答的质量」打分，用来发现遗漏与自相矛盾。两个设计问题：

1. 分数取什么？模型输出的是各档位上的概率分布。
2. 低分要不要打断对话？打断有真实代价（多消耗一轮、可能误打断）。

备选（分数）：取 argmax 档位（丢掉「几乎并列」的信息，三档太粗）；让模型直接给数字（不可校验、语义易漂）。
备选（介入）：任何低分都补完（低置信噪声会频繁误触发）；完全不介入（只有日志，价值低）。

## Decision

- 题型用 `score`，档位是**可配 rubric**（默认三档，从「明显答非所问」到「完整准确」，2–10 档）。
- 分数 = 各档位概率的加权均值，因此可能是小数（如 1.4），满分等于顶档号。相比 argmax，它保留了「几乎确定 1 分」与「1/2 之间摇摆」的区别。
- 低分线 `lowScoreThreshold` 默认 1（`score <= 1` 视为偏低）。
- **补完要置信度**：`confidence >= minConfidence`（默认 0.4）且 `mode = 'steer'` 才追加一条补完提示；同一回合最多一次（预算只在成功 steer 时消耗）。
- **低置信低分标记为噪声**：置信度低于趋势门槛的低分仍记录，但打 `lowConfidence: true`，不计入趋势、不触发补完。
- 趋势告警（连续 N 次高置信低分 → 图标变色）**只读**：不改变任何介入行为，只提示任务变难或模型波动。
- 只评判本回合最终回复，不读中间过程；提取「请求主题」用于日志时剥离注入的记忆上下文块。

## Consequences

- 分数可小数，因此日志与 UI 必须按小数渲染，**不能**用整数校验（否则合法小数会被判成「响应格式不符」）。
- 默认 `observe`：低分只入日志与统计。用户开启 steer 后才可能被打断——打断是显式选择。
- 噪声标记让「模型没把握的低分」不污染趋势；代价是真实下滑若恰逢低置信会被当噪声，需看日志原文。
- 补完提示以用户名义追加，模型看到的是普通用户消息。这是特性（对话自然）也是风险（用户可能不解为何多一轮），因此决策日志必须能追溯：低分标记、置信度、请求主题都要可见。
