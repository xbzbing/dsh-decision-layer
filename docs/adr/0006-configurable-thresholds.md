# ADR-0006：介入阈值全部可配，防循环阈值除外

- 状态：Accepted（2026-10-26）
- 相关：`service/config-store.mjs`、`src/client/config-form.tsx`、`README.md` 的配置说明、ADR-0003、ADR-0007、ADR-0008、ADR-0010

## Context

0.6.x 之前，多数阈值是代码里的常量：门控拦截置信度最初是 0.7 的硬编码常量，写在 `danger-gate.mjs` 且调用点从不传参，自检与完成核对的补完置信度 0.4 只是构造参数默认值，趋势门槛只能手改 `config.json`。这些阈值全是**未经验证的启发式**，却没有任何运行期调节手段——想验证「这个阈值是不是太高」只能改代码再重启。

同时，隐藏的默认值会误导人：配置页只显示了实际生效值的子集，用户以为「没得调」。

备选：保持常量（实验成本高，与「体验版、待校准」的定位矛盾）；改成环境变量（与既有 JSON 配置形成两套来源，且进程内不易热更新）；只暴露一部分（用户无法自洽地调）。

## Decision

所有自动介入的阈值都进配置，落在 `~/.config/dsh-decision-layer/config.json` 与配置页「高级配置」：

| 块 | 字段 | 默认 | 含义 |
| --- | --- | --- | --- |
| `gateSettings` | `minConfidence` | 0.6 | 门控拦截置信度 |
| `checkSettings` | `minConfidence` | 0.4 | 自检补完置信度 |
| `checkSettings` | `lowScoreThreshold` | 1 | 低分线（评分 0–2） |
| `checkSettings` | `trendMinConfidence` / `trendRun` / `trendSevereRun` | 0.6 / 3 / 5 | 趋势告警门槛 |
| `checkSettings` | `rubric` | 3 档 | 评分档位（2–10 档） |
| `narrowSettings` | `threshold` / `maxCandidates` / `batchMode` | 0.3 / 20 / `auto` | 收窄摘除线、候选上限、分批策略 |
| `completeSettings` | `minConfidence` / `minConditions` | 0.4 / 2 | 完成核对补完置信度、最少条件数 |

- 概率类一律 `[0, 1]`，整数类给出闭区间；跨字段约束（`trendSevereRun > trendRun`）在服务端校验、配置页夹取。
- **防循环的重复阈值（3）不进配置**：它是确定性本地保护，与模型无关，不属于「启发式待校准」的范畴（ADR-0010）。
- 默认值同时出现在服务端常量与配置页（后者用于把未设置的字段显示成生效值）。允许重复，但必须有测试盯住一致；彻底消除需要一份共享常量模块，尚未做。

## Consequences

- 阈值可以在不重启的情况下被真实流量检验——这是本插件的核心研究价值。
- 代价：默认值有了多个副本（服务端常量、配置页镜像、README 表格）。当前靠注释标注来源，漂移风险由测试与 review 兜。
- 阈值可配意味着**用户可以把门控调成近乎失效**（`minConfidence: 1` 配一个低置信模型）。这是有意的：配置权在用户，插件只保证方向性可解释（调低更容易拦、调高更宽松）。
- 门控默认值已从 0.7 下调到 0.6（2026-10-26）。本机 150 条门控观测里，`deny` 建议的置信度全部 ≤0.12，两档在现有数据上没有行为差异——下调是为「后端将来给出更高置信的 deny 时更倾向拦截」，不是对既有误判的修正。
- 默认值仍是未标定的启发式，因此 0.6.x 继续标为体验版；实测校准后应新写 ADR 记录新值，而不是改写本文。
