# ADR-0004：失败即放行，但爆炸半径必须有界

- 状态：Accepted（2026-10-26）
- 相关：`service/dsh.mjs` 的 `featureOn`、`service/danger-gate.mjs` 的 `resolveMinConfidence`、`service/config-store.mjs`、`tests/dsh.test.mjs`、ADR-0005

## Context

两条相反的要求同时成立：

1. 裁决后端不可用、响应不合法时，**不能**阻断 agent —— 否则裁决层成了单点故障；
2. 「失败即放行」只能作用于**裁决本身**，不能把周边机制一起拖下水。

第二轮代码评审发现第 2 条被违反了。`featureOn` 在 `tools/pre-execute` 瀑布里直接 `await resolveConfig()`，而配置校验是严格的（越界、拼错字段名、类型不符都抛错）。宿主对 hook 抛错的处理是 `catch → toolErrorResult`，工具**不派发**。于是配置里写错一个值，所有工具调用（含 `read`、`edit`）全部失败——用户连修复配置文件的手段都没有了。这与插件「安全网」的定位正好相反。

备选：把配置校验放宽成「忽略非法字段」（错误静默，且要把五个校验器一起改）；给整个 hook 包一层 try/catch（会把真正的逻辑 bug 一起吞掉，且拦截失败时的语义更难解释）。

## Decision

- **裁决失败不介入**：后端 `unreachable` / `http-error` / `invalid-response`、置信度不足、响应缺字段，一律 pass-through，按宿主原路径执行。
- **配置读取失败降级，不抛错**：热路径上的每次配置读取（功能开关、门控置信度、危险规则）各自容错，失败时退到**安全默认**而不是「关闭功能」：功能开关视为全开，门控阈值回落默认值（0.6），危险规则回落内置集。
- 降级方向必须**更保守**而不是更宽松：`minConfidence` 解析失败回落默认值 0.6，**不是** 0（0 会让每个 `deny` 都拦）。
- 每条降级都要有测试，且该测试**去掉降级后必须变红**。

## Consequences

- 配置写坏的最坏后果是「阈值退回默认、规则退回内置集」，agent 仍可用——可恢复。
- 代价：配置错误不再以「工具全挂」这种响亮的方式暴露，用户可能长期跑在默认阈值上而不自知。因此配置页的 GET 仍对非法配置报错（可见），只有决策热路径降级（可用）。
- 「安全默认」需要每个决策点各自定义一次，新增决策点时容易漏；当前只有门控有测试盯住，其余靠 review。
- 由此确立一个模式：**跨越信任边界（配置、外部输入）的读取要么校验后使用，要么容错降级**，不允许把异常直接抛进宿主 hook。
